# Model B B0–B1 contract

## Input boundary

Model B never reruns phoneme recognition.  Its timing input is the `alignment.phonemes`
array emitted by Model A A2:

```json
{
  "phoneme": "ky",
  "index": 6,
  "startMs": 280.0,
  "endMs": 320.0
}
```

The audio must be the same 16 kHz mono sentence WAV used by Model A.  Do not
extract prosody from a different trim: doing so breaks the shared time axis.

## B0 rules

| Phoneme sequence | B0 output |
| --- | --- |
| `k a` | one `ka` mora |
| `ky o` | one `kyo` mora |
| `N` | one moraic-nasal mora |
| `cl` | one sokuon mora |
| `sil`, `pau` | a non-scored pause span |
| `o o` | two morae, linked as an explicit long-vowel pair |

The last rule deliberately does not collapse a long vowel.  Japanese timing
is mora-based, so the continuation must retain its own duration.  Other
orthographic long-vowel patterns (such as `e i` and `o u`) need reference text
or kana reading; B0 will not infer them only from a phoneme stream.

## B1 output

Each scored mora receives pitch/energy observations, including:

- voiced-frame count and ratio;
- F0 median/min/max in Hz (diagnostic only);
- start/end/median/peak F0 in semitones relative to the utterance median;
- F0 slope and peak position;
- duration and RMS energy.

Unvoiced morae, `cl`, and pause spans remain valid rows, but their F0 values
are `null`.  That is evidence for later quality/scoring logic — not a missing
record or an automatic error.

## Method and production boundary

Praat recommends filtered autocorrelation for intonation work.  The current
Python package embeds an older Praat and exposes raw AC, so the JSON method is
explicitly `raw_ac_fallback`.  Before B2 learner-vs-native comparison or any
user-facing grade, replace this backend with a reproducible current-Praat
filtered-AC adapter and version the feature schema again.
